Using the CEDAR REST API

Every request includes an Authorization header built from one of your API keys. The examples below use your active key.

Header name
Authorization
Header value
apiKey {{activeApiKey()}}

The examples use cURL. Resource IDs (a template's or folder's @id) are full URLs and must be URL-encoded when placed in a path or query string — replace {TEMPLATE_ID} below with your encoded template id.

List your home folder contents Everything at the top level of your workspace. 
curl{{curlOpts()}} "{{urlService.base()}}/folders/{{$root.cedarUser.getHomeFolderIdEncoded()}}/contents?resource_types=instance,template,folder,element" \
  -H "Authorization: apiKey {{activeApiKey()}}"
List resources shared with you Templates and instances other users have shared. 
curl{{curlOpts()}} "{{urlService.base()}}/search?sharing=shared-with-me" \
  -H "Authorization: apiKey {{activeApiKey()}}"
Retrieve a template Fetch a single template by its URL-encoded @id. 
curl{{curlOpts()}} "{{urlService.base()}}/templates/{TEMPLATE_ID}" \
  -H "Authorization: apiKey {{activeApiKey()}}"
Create a template POST a template JSON; the server assigns the @id. Omit folder_id to use your home folder. 
curl{{curlOpts()}} -X POST "{{urlService.base()}}/templates?folder_id={{$root.cedarUser.getHomeFolderIdEncoded()}}" \
  -H "Authorization: apiKey {{activeApiKey()}}" \
  -H "Content-Type: application/json" \
  -d @template.json
Create or update a template with a specific @id PUT to the id: creates the template with that id, or updates it if it already exists. The body's @id must match the URL. 
curl{{curlOpts()}} -X PUT "{{urlService.base()}}/templates/{TEMPLATE_ID}" \
  -H "Authorization: apiKey {{activeApiKey()}}" \
  -H "Content-Type: application/json" \
  -d @template.json
Get all instances of a template Search for every instance based on a given template. 
curl{{curlOpts()}} "{{urlService.base()}}/search?is_based_on={TEMPLATE_ID}&resource_types=instance" \
  -H "Authorization: apiKey {{activeApiKey()}}"
